写在前面

时隔三年重新开始写博客。这三年经历了读研、出国和考博，也曾多次想把过去没有写完的内容继续整理下来，但最终一直没有真正开始。索性将之前的文章清理掉，从头重新记录。

写这篇文章最直接的原因，是想给组里的师兄、师姐、师弟和师妹整理一份相对完整的 Python 环境配置教程，同时也介绍一些常见机器学习项目中比较实用的环境管理方法。

对于科研工作而言，环境配置本身并不是研究的核心，却经常消耗大量时间。Python 版本不一致、依赖冲突、虚拟环境混乱、深度学习框架安装失败，这些问题对于刚接触 Python 的同学尤其常见。

因此，本文希望尽可能提供一套简单、统一且具有较好可复现性的 Python 项目管理方式。按照本文的流程进行配置后，大多数常规科研项目都可以使用相似的方法完成环境初始化与依赖管理，尽量避免让“配置环境”成为科研工作的额外负担。

0 - pip 是什么，uv 又是什么？

Python 自带大量标准库，用于提供文件操作、系统接口、JSON 解析等基础功能，例如 io、sys 和 json。但在机器学习、数据分析和科学计算中，我们往往还需要使用大量第三方库，例如 NumPy、Pandas、scikit-learn 和 PyTorch 等。

在大多数 Python 安装环境中，pip 是最常见的第三方包管理工具。通过一条简单的命令：

即可从 PyPI（Python Package Index）下载并安装所需的第三方库。

这种方式非常方便，但在实际科研项目中也存在一些问题。

首先，如果直接在全局 Python 环境中执行 pip install，不同项目所需的依赖会逐渐混杂在同一个环境中。当两个项目依赖同一个库的不同版本时，就可能出现版本冲突。此时往往需要反复执行安装、卸载或降级操作，不仅增加环境维护成本，也会降低项目的可复现性。

当然，一个自然的解决方案是：为每个项目建立独立的虚拟环境。

但新的问题随之出现。例如，在多个机器学习项目中分别创建虚拟环境后，PyTorch 等体积较大的依赖可能会被重复下载和存储。随着项目数量增加，环境初始化时间和磁盘占用都会逐渐成为问题。

如果能够将已经下载过的包统一缓存，并在不同项目之间复用，就可以显著减少重复下载和安装开销。

这正是 uv 的优势之一。

uv 的官方定位是：

An extremely fast Python package and project manager, written in Rust.

即：一个使用 Rust 编写的高性能 Python 包与项目管理工具。

官方提供的性能测试如下：

与传统的 Python 工具链相比，uv 将过去由多个工具分别承担的功能进行了较大程度的整合。例如，它可以承担许多原本由 pip、pipx、Poetry、virtualenv 和 pyenv 等工具完成的工作，包括：

  • Python 版本管理；
  • 虚拟环境创建；
  • 项目初始化；
  • 依赖安装与解析；
  • 依赖版本锁定；
  • 包缓存与复用；
  • Python 脚本和项目命令运行。

与此同时，uv 使用 Rust 实现，并针对依赖解析、下载和缓存机制进行了优化。在许多典型场景下，其执行速度可以显著快于传统 Python 包管理工具。

对于科研项目而言，它最大的价值并不仅仅是“快”，而是能够提供一套相对统一的 Python 项目管理方式。

1 - 安装 uv

uv 可以通过 pip 安装，也可以直接安装而不依赖现有 Python 环境。

这里更推荐直接安装。

原因很简单：如果 uv 本身依赖某个已有 Python 环境，那么一旦该 Python 环境出现问题，uv 的可用性也可能受到影响。直接安装可以减少这种额外依赖，使其作为独立的环境管理工具运行。

3 - 依赖管理和运行代码

前面多次提到了 pyproject.toml。那么，它究竟是什么？

简单来说，pyproject.toml 是现代 Python 项目中非常重要的统一配置文件。

过去，一个 Python 项目中可能同时存在：

等多个配置文件，不同工具分别读取不同配置，项目结构容易变得较为分散。

pyproject.toml 的引入，使 Python 项目能够通过一个标准化入口描述构建系统、项目元数据、依赖、开发工具配置等信息。配合 uv 后，还可以进一步统一 Python 版本、依赖解析与虚拟环境管理。

  • [project] 用于描述项目基本信息及核心依赖；

uv.lock 的作用尤其重要。

pyproject.toml 更多描述的是“允许使用哪些版本”，而 uv.lock 会记录经过解析后实际使用的具体依赖版本。将它提交到 Git 后，其他人在重新执行 uv sync 时，就更容易获得与原项目一致的依赖环境。

5 - PyTorch 安装

机器学习项目中，相对容易出现环境问题的框架之一是 PyTorch。

与普通 Python 库不同，PyTorch 的安装通常还涉及操作系统、硬件平台以及 CUDA 版本等因素。尤其是在使用 NVIDIA GPU 时，需要确保安装的 PyTorch 构建版本与目标 CUDA 环境相匹配。

6 - 结语

Python 环境配置本身并不是一个复杂的研究问题，但它往往会在实际科研过程中产生大量额外成本。

传统工作流中，我们可能需要分别处理 Python 版本、虚拟环境、依赖安装、依赖锁定以及项目运行等问题。当项目数量增加后，不同工具和环境之间的差异很容易导致依赖冲突、版本不一致以及代码难以复现。
